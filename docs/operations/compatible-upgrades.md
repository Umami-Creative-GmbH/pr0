# Compatible upgrades

Desktop uploads require protocol 1 together with `pr0-search-v1-ucd17`. Discovery with `GET /api/v1/capabilities?negotiation=1` returns explicit supported pairs and a 90-day support policy. Discovery without the query retains the legacy strict response. A new desktop also accepts a legacy server's protocol list and normalization when they contain its pair. Unsupported pairs stop both prompt and usage uploads before freezing new work; browsing, copying, pending identities and exact variants remain local. The UI directs users to update the app or contact their self-hosted operator, then retry.

Keep every contract used by the current desktop and releases shipped in the preceding 90 days. There are no published GitHub releases as of 2026-09-21; the current development version is 0.1.0. The implemented predecessor matrix is SQLite 1–4 to 5, plus repair of version-5 derived indexes. Before publishing a release, record its date, protocol/normalization pair and local schema in release notes and add its retained-data fixture to this matrix. Never retire protocol 1 or change its normalization in place. Introduce new semantics at an explicit versioned boundary and serve the previous pair throughout the support window. Protocol age alone does not expire local browsing.

## Desktop storage

Rust checks the schema before writes and rejects versions above 5. One `BEGIN IMMEDIATE` transaction covers the entire ordered migration chain, transformations and version updates. Before upgrading an existing library, preflight uses committed SQLite page count × page size, three copies plus a 16 MiB reserve, against Windows space available to the current user. This is a conservative admission estimate; an actual allocation failure still rolls back the transaction.

While holding the writer reservation, the SQLite backup API copies a consistent committed snapshot, including WAL records, outbox UUIDs, frozen envelopes, baselines, receipts and pending usage. The backup's primary tables are checked, its contents flushed, and Windows publishes it with write-through replacement before migration starts. Backups live next to the primary partition as `library-<instance>-<account>.backup-v<N>.sqlite`. They inherit the same user-directory protection as ordinary local prompt storage. Confirmed sign-out/account cleanup includes backups and exact known sidecars. A backup is not a second account or a sync source.

An incompatible, missing or corrupt derived index is rebuilt inside a SQLite transaction and activated with its version and checkpoint. Old readers retain the committed projection until activation. Rebuild failure leaves primary browsing/copying available and reports recovery guidance; editing can be retried after storage recovery and restarting pr0. Never delete the primary library or clear the outbox to repair search. Newer-schema errors require the matching or newer app, not manual `user_version` changes. For backup restoration, stop pr0 first, preserve the failed partition for diagnosis, and use a compatible binary; never copy a live main database without its WAL.

## Server deployment

Migrations are an explicit Bun command, never application startup behavior. The Compose `accounts` service builds the `migration-runtime` target, which includes Bun and native PostgreSQL 17 backup tools. It mounts the database volume read-only for space measurement and a separate `migration-backups` volume for dumps.

1. Close ingress and stop web, mail and search/deletion workers before upgrading a legacy deployment. Legacy binaries cannot observe the new migration admission gate. Preserve all database, ledger, search and backup volumes.
2. Build the web image and migration target. Run `docker compose --profile operations run --rm --build accounts migrate` with the existing instance configuration and credentials.
3. The single coordinator holds PostgreSQL advisory lock 24001, validates the complete ordered checksum history and rejects unknown/newer migrations. It records `draining`, `preflight`, `migrating`, and `ready` checkpoints. Each DDL change, history record and completed checkpoint commits atomically. HTTP admission observes the gate under its admission lock; readiness stays unavailable during interruption/failure.
4. For an existing schema upgrade, preflight measures the database size and both mounted filesystems, creates an exclusive 0600 custom-format `pg_dump`, flushes it, checks its catalogue with `pg_restore`, and records its name/SHA-256. Failure leaves admission closed. A fresh empty database needs no predecessor backup. Direct CLI use requires `PR0_MIGRATION_BACKUPS`, `PR0_DATABASE_VOLUME` on the actual database host, and matching PostgreSQL tools. Do not substitute an unrelated local directory for a remote database volume.
5. Restart the matching application image and workers, check readiness and a library read, then reopen ingress. Retry the coordinator after repairing a failure; completed DDL is not replayed. Never remove checksum/history rows in production.

Migration 19 is additive and retains existing protocol, normalization, cursor and recovery-epoch semantics. `minimum_server_migration` is the binary compatibility floor: future additive migrations may leave it unchanged; a contract migration must raise it only after the full support window and must version affected cursors/projections together. A compatible predecessor may read a completed expanded schema; an older coordinator may never migrate it. Restore uses the existing deletion-safe restore procedure, including a new recovery epoch and independent deletion-evidence replay. Restoring a dump directly into a serving instance is unsafe.

Migration dumps are local safety copies containing account data, not encrypted off-server disaster-recovery backups. Include the `migration-backups` volume in the operator's existing encrypted backup and maximum-30-day retention procedure, including failed partial dumps. Remove expired copies during the operator's daily retention job and alert on cleanup failure. `pg_restore --list` is a catalogue check, not a substitute for the required restore rehearsal.
