# Monorepo implementation plan

**Goal:** establish shared web/desktop infrastructure without introducing domain features.

**Architecture:** Bun workspaces coordinated by Turborepo; Next.js owns REST handlers, Tauri uses Vite; both consume UI and validated REST/Query packages.

**Tech stack:** existing Next.js 16.3.5, React 19.2.8, shadcn, Tailwind 4 and Ultracite; Tauri 2, TanStack Query 5, Zod 4.

**Spec:** `docs/superpowers/specs/2026-09-19-monorepo-design.md`.

## Constraints

- Preserve existing setup changes and Bun 1.4.2.
- No domain logic or unnecessary Server Actions; no TanStack Store yet.
- Shared UI is platform independent; production desktop API URL is explicit HTTPS.
- Work in the existing checkout so the user's uncommitted setup is included.

## Tasks

- [x] Move the existing Next.js app to `apps/web`; extract shadcn button, utilities and CSS into `packages/ui`. Configure source exports, workspace manifests, shared TypeScript options, Tailwind source discovery, and shadcn aliases.
- [x] Add `packages/api-contract` and `packages/api-client`. Verify URL handling, error handling, payload validation, cancellation and query cache identity with Bun tests. Add health Route Handler, CORS helper, OpenAPI document and Swagger page in the web app.
- [x] Add Vite/React frontend and Tauri Rust/configuration under `apps/desktop`. Use shared UI/Query packages in both entry points. Require an HTTPS production API origin; configure Tauri CSP for that origin.
- [x] Replace root scripts with Turbo tasks, retain centralized Ultracite presets, update ignores and README, and add CI checks.
- [x] Run `bun install`, `bun run fix`, `bun run check`, `bun run typecheck`, `bun run test`, `bun run build`, React Doctor and `cargo check`. Smoke-test web, desktop frontend, health, CORS, OpenAPI and Swagger. Review the final diff and document actual verification results.

## Verification results

- Frozen-lockfile installation, Ultracite check and all five TypeScript workspace checks pass.
- Fourteen Bun tests pass: REST response validation, failures, cancellation, query cache separation, CORS and API routes.
- Both production frontend builds pass with `VITE_API_BASE_URL=https://api.example.com` as a build-only placeholder.
- Web and Vite desktop screens connect successfully in the browser; retry works. Swagger's Try it out returns HTTP 200 and the expected payload. Production Swagger assets and schema rendering were also verified.
- `cargo check` and a Tauri Windows debug build with `--no-bundle --ci` pass. The executable is generated successfully. Rust emitted a non-fatal incremental-cache finalization permission warning on this drive.
- React Doctor full scan: 96/100, with one warning for the preserved shadcn button/variant exports. Its changed-file scan skipped untracked workspace files, so the full scan was used.
- `cargo fmt --check` could not run because this machine has no rustfmt command. CI installs rustfmt explicitly. CI itself has not been run remotely; installers and signing were not tested.
- Independent code review findings about development CSP and Turbo environment forwarding were fixed. A follow-up review found no important issues in the standalone Swagger packaging or caching.

Swagger uses the official prebuilt browser distribution because its React package's OpenAPI 3.1 resolver failed at runtime under Turbopack. Local assets are generated before development/build and included in Turbo's cached outputs.
